# 会话流审查与优化方案(对标 Cursor / Claude Code)

## Context

用户要求逐项审查会话流里各种条目与工具行的展示与交互,对标 Cursor(Agent 面板的动效与视觉)和 Claude Code(CLI 的信息表达),找出不符合最佳实践的地方并给出方案。

已通读的实现:`timeline.rs`(分发 / 思考 / 处理中)、`row_groups.rs`(显示行:工具组 / 子 Agent 组 / 回合折叠 / 处理中)、`tool_card.rs` + `tool_present.rs`(工具行与展开内容)、`tool_group.rs`(折叠组 + 最新一步滑动)、`turn_digest.rs`、`turn_footer.rs`、`subagent_card.rs`、`agent_group.rs`、`cards.rs`(待办 / 画布 / 改动 / 提示)、`ask_cards.rs` / `dock_cards.rs` / `wizard_card.rs`、`code_box.rs`、`rich_text.rs`、`task_ui.rs`、`chat_scroll.rs`;归约 `loom-core/session.rs`、翻译 `loom-claude/translate.rs`。

**整体评价**:骨架已对齐主流做法——成功不打勾、悬停才出箭头、浏览类工具折叠成「读取了 3 个文件」、「已工作 12分8秒」回合折叠、最新一步滑入、待处理卡放输入框上方、长输出限高。问题集中在:**待办展示、思考流式、动效缺失、节奏不统一、若干失效的可点击元素、权限卡无键盘**。

---

## 审查发现与方案(按优先级)

### P0 — 明显问题 / 缺陷

1. **待办每次 TodoWrite 都生成一张完整卡片,刷屏**
   - 现状:`translate.rs:447` 用 tool_use id 作待办 id,每次更新都是新条目;`cards::render_todos` 每张都画全量清单。`activeForm`(进行中文案)被丢弃。
   - 对标:Cursor 把待办固定在输入框上方(可折叠,「3/7」),时间线里只留一行「更新了待办」;Claude Code 的转圈状态行显示当前项的 `activeForm`(如「正在写测试…」)。
   - 方案:
     - `TodoItem` 加 `active_form: Option<String>`(serde default),`parse_todos` 读取。
     - 新增 `todo_dock.rs`:输入框上方(与任务坞同层)固定显示**最新一份**待办,折叠时一行「▸ 待办 3/7 · 当前:正在写测试」,展开列全量;全部完成后 3 秒自动收起。
     - 时间线里的待办条目改成一行差异摘要(`cards::render_todos` → `render_todo_delta`):「✓ 完成 X」「▶ 开始 Y」,比较同会话上一份待办;首份显示「创建了 N 项待办」;点击展开当次全量。
     - 「处理中」行与折叠组「最新一步」在有进行中待办时优先显示其 `active_form`。
   - 文件:`loom-core/timeline.rs`、`loom-claude/translate.rs`、`loom-app/cards.rs`、新 `todo_dock.rs`、`timeline.rs::render_working`、挂载点(任务坞所在的 composer 区)。

2. **思考流式时「先展开、超过 400 字节突然消失」**
   - 现状:`timeline.rs::render_thinking` 中 `streaming && text.len() < 400` 才显示正文,跨过阈值整块消失,行高骤变。
   - 对标:Cursor 在思考中显示固定高度(约 3–4 行)的尾部滚动窗,顶部渐隐,结束后收成「已思考 N 秒」。
   - 方案:流式时正文放进固定 `max_h(px(60.))` 的容器,`code_box` 同款 `ScrollHandle::scroll_to_bottom` 贴底跟随,顶部叠一层背景色→透明的渐变;结束后按原逻辑折叠。

3. **失效的可点击元素(悬停有反馈,点了没反应)**
   - `tool_card.rs` Diff 头的路径:派发 `ide_window::OpenPath`,注释承认 Agent 窗口里无处理者,但仍有下划线悬停。→ 改为 `UiRequest::OpenFile(path)`(工具行「打开文件」按钮已用这条通路)。
   - 终端块的「在终端面板查看」:IDE 窗口里无处理者。→ 由调用方传入「是否可用」(或在 IDE 对话栏处理 `ViewAgentRun` 打开底部终端),不可用时不渲染。

4. **回合被中断没有任何终止标记**
   - 现状:`session.rs::finish_streaming(cancelled)` 只把工具标成「已中断」;如果中断发生在正文流式中,时间线看起来像正常结束。
   - 对标:Claude Code 显示「⎿ Interrupted · What should Claude do instead?」。
   - 方案:取消时在末尾追加 `Notice { level: Info, text: "已中断" }`(复用现有提示条目,不新增类型),渲染成一行灰字 + `CirclePause` 图标(见 P1-7 的提示样式)。补 `session.rs` 单测。

### P1 — 交互与视觉的最佳实践差距

5. **没有入场动效,内容「蹦」出来**
   - 对标:Cursor 新行 150ms 淡入 + 4px 上移;展开箭头旋转。
   - 方案:
     - `SessionModel` 记 `appeared: HashMap<String, Instant>`(条目首次在**实时回合**进入时记录,回放不记);`timeline::render_row` 对 300ms 内出现的行包 `with_animation`(opacity 0→1、`mt` 4→0,`ease_out_quint`),动画 id 用条目 id。超时后不再包,避免虚拟列表滚回视口时重播。
     - 箭头:统一一个 `ui::chevron(expanded, id)`,用 `svg().with_transformation(rotate)` 做 120ms 旋转,替换 tool_card / tool_group / turn_digest / agent_group / subagent_card / thinking 里各自的 `ChevronDown/Right` 切换。
     - 不做高度动画(虚拟列表重测成本高,Cursor 的展开本身也是瞬时 + 淡入),展开内容只做 120ms 淡入。

6. **垂直节奏不统一**
   - 现状:每行一律 `py(5.)`;各种标题行高 24 / 26 / 28 / py 3 混用;字号 11/12/12.5/13/14 混杂。
   - 对标:Cursor 同一回合内工具行紧凑(约 2px 间隔),正文与工具之间约 8px,新用户消息前留更大间隔。
   - 方案:新增 `flow_style.rs` 常量:`ROW_H = 26`(所有一行式标题:工具、工具组、回合折叠、子 Agent 组、权限结果、任务通知)、字号三档 `TEXT_BODY 14 / TEXT_ROW 13 / TEXT_META 11.5`;`render_row` 按「上一行类型 → 本行类型」给语义间距:工具↔工具 1px、正文↔工具 6px、→用户消息 18px、其余 5px。

7. **错误提示可读性差、不可操作**
   - 现状:`cards::render_notice` 整段文字染成红 / 黄,`muted` 底;没有动作。
   - 对标:Cursor 错误卡:中性正文 + 彩色图标 + 左侧色条,带「重试」「复制」。
   - 方案:正文改 `foreground`,图标与 2px 左色条用级别色;Error 级别加「重试」(重发上一条用户消息,复用 `user_message` 已有的重试逻辑)与「复制」;Info 级别(如 P0-4 的「已中断」)只是一行灰字,无底色。

8. **权限卡没有键盘操作与危险提示**
   - 对标:Claude Code 用 1/2/3 选择、Esc 拒绝;Cursor「⏎ 接受 / ⌘⌫ 拒绝」。
   - 方案:`dock_cards::permission` 加 `key_context("PermissionCard")` 与 `on_key_down`(⏎ = 单次允许,数字键选对应项,Esc = 拒绝一次),按钮文案后缀快捷键提示(与向导卡「跳过 ⎋」一致);卡片出现时抢焦点(同 `wizard_focus` 的做法)。命令含 `rm -rf`、`git push --force`、`sudo` 等时标题图标与边框用 `danger`。
   - 同时工具行在等待权限时显示「等待批准」(warning 色)而不是孤零零的时钟图标:`tool_card::render_tool` 查 `pending_of` 里是否有同 tool id 的权限请求。

9. **编辑类工具默认看不到改动**
   - 现状:标准档下编辑是一行「编辑 a.rs +3 −1」,必须点开。
   - 对标:Claude Code 每次 Edit 都直接显示差异;Cursor 显示带文件名的差异卡片(默认几行预览,可展开)。
   - 方案:标准档下 Edit / Write 默认展开,但 Diff 用更小的收起高度(新增 `code_box::Fold` 的 `collapsed_h` 参数,编辑预览 120px ≈ 7 行),精简档维持折叠。`row_groups::expands_in_detailed` 改名 `expands_by_default(tool, density)` 统一判断。

10. **命令行只显示说明,看不到真正执行的命令**
    - 现状:`described` 时行内只有 Agent 写的说明。
    - 方案:说明之后追加灰色等宽、截断的命令首行(`code_hl::shell_text`,`text_size 11.5`,`opacity 0.7`),说明优先占宽。Claude Code 两者都显示。

11. **工具行信息补全**(`tool_present.rs`)
    - Grep / Glob:附注加结果数(由结果文本行数得出,「12 处」),对标 Cursor「Grepped … · 12 results」。
    - WebFetch:对象显示域名 + 截断路径,而不是整条 URL。
    - MCP:动词位放服务名小胶囊(`pill`),对象显示工具名 + 首个字符串参数。
    - 补测试。

12. **状态指示器不统一**
    - 现状:工具行 / 工具组 / 子 Agent 用 `Spinner`,思考 / 处理中用 `appearance::glyph_spinner`。
    - 方案:时间线内一律 `glyph_spinner`(随外观偏好),尺寸统一 12px;`Spinner` 只留给按钮内。

### P2 — 打磨

13. **回复操作条常驻**:`turn_footer` 每个回合都显示复制 / 分支 / 元信息,长会话很吵。对标 Cursor / Claude 桌面版:最后一个回合常驻,其余悬停显示(高度保留 `FOOTER_H`,不跳动)。顺手修正 `FOOTER_H` 注释与实际行为不一致。
14. **代码块复制无反馈**:`code_box::render_code` 的复制按钮改为点后 1.5 秒显示对勾(复用 `SessionModel::mark_copied`)。
15. **回合折叠行悬停反馈缺失**:`turn_digest` 标题行没有 `hover` 背景,和其他可点击标题不一致;补上,并在标题后附「N 次工具」灰字。
16. **文件超长**:`tool_card.rs`(318 行)超出 300 行约定,实施 P1-9/10 时把 `render_content` 拆到 `tool_content.rs`;`row_groups.rs`、`user_message.rs` 本次不动。

## 关键复用

- 贴底跟随滚动:`code_box::handle_for` / `fold_body`
- 展开状态:`SessionModel::is_expanded / toggle`,复制标记 `mark_copied`
- 焦点与键盘:`wizard_card` 的 `wizard_focus` + `on_key_down` 模式
- 动画:`tool_group::latest_step` 里的 `Animation + ease_out_quint`
- 待处理请求:`dock_cards::pending_of`
- 文案 / 计时:`appearance::status_line`、`verb_text`、`elapsed_text`
